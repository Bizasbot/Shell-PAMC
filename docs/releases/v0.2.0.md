# Oh My CPA v0.2.0

## Agent

- Una respuesta puede incluir una interfaz. El modelo dibuja con una herramienta de visualización,
  `render_ui`, y la consola muestra el resultado donde se ubica la llamada dentro de la
  respuesta, dentro de un entorno aislado (sandbox) exclusivo para scripts que no carga nada de la red. Una
  interfaz generada se compone a partir del propio kit de la consola —estadísticas, tablas,
  gráficos, diagramas, pestañas y controles—, lee las filas que el resultado de una capacidad anterior
  congeló y se dibuja mientras aún se está escribiendo.
- `/` abre los comandos de la página y `@` completa un modelo, un alias de clave de cliente
  o el nombre de una capacidad; la flecha Arriba recupera los mensajes enviados. `/ui` y `/text` configuran cómo se
  presenta la siguiente respuesta.
- Un mensaje puede contener hasta cuatro imágenes y hasta cuatro archivos de texto. Las imágenes se
  almacenan encriptadas junto a la conversación mientras su turno forme parte
  de la misma.
- El turno más reciente se puede volver a intentar o editar, el modelo puede ofrecer preguntas de
  seguimiento y los detalles de una llamada se abren debajo de la misma. Un anillo debajo del campo de escritura
  indica qué porcentaje de la ventana de contexto del modelo ocupa la conversación.
- Las ejecuciones y sesiones no tienen límite propio de la consola en cuanto a tokens, rondas
  o duración. Una conversación larga incrementa la base de datos y el coste de cada petición;
  utiliza Nueva conversación para liberarla.

## Endpoints de inferencia

- El Agent y el Playground envían una conversación a los endpoints Chat Completions,
  Responses o Messages de CPA, seleccionados mediante un chip en el campo de escritura y
  recordados. Los turnos, diagnósticos, uso y recuperación se leen de la misma manera sin importar
  qué endpoint haya respondido.
- El esfuerzo de razonamiento se escribe en el formato propio de cada endpoint. En Messages se
  envía como pensamiento adaptativo con un esfuerzo de salida, y `none` desactiva
  el pensamiento; un modelo o compilación de CPA anterior a ese formato lo rechaza, y
  el cuerpo de petición personalizado del Playground puede especificar otro.
- En Responses y Messages, el cuerpo de petición personalizado del Playground no puede
  reemplazar la conversación (`input`, `messages`). Cualquier otro campo sigue
  sobrescribiendo.
- Una petición a Messages siempre especifica un límite de tokens: 4096 desde el Playground cuando
  no se establece ninguno, 16384 desde el Agent.

## Playground

- La clave, el modelo y el esfuerzo de razonamiento se seleccionan mediante chips en el campo de escritura, al igual que
  en la página del Agent. Los dos selectores de la cabecera y su acción de actualización se eliminan;
  la actualización se encuentra en la lista del chip de modelo.
- El esfuerzo de razonamiento es uno de los niveles con nombre. Un nivel específico del proveedor se establece
  a través del cuerpo de petición personalizado, y el botón Restablecer del panel ya no borra el esfuerzo.
- Se conserva un modelo seleccionado justo antes de una recarga, y el cuadro de mensajes adquiere el foco
  antes de que se seleccione un modelo.

## Agentes externos

- El registro de capacidades se sirve a través de MCP Streamable HTTP en
  `<console URL>/api/mcp`, autenticado mediante la clave de gestión de CPA como un token de portador (bearer token),
  junto con el puente stdio existente `oh-my-cpa mcp`. No es necesario instalar nada
  en el lugar donde se ejecuta el agente.
- Una operación que requiere aprobación devuelve un enlace a una pantalla de consentimiento en
  la consola, donde el operador con sesión iniciada la permite o deniega. Un agente externo
  puede preparar una operación y esperar la decisión; no puede aprobarla.
- La guía de conexión de la página del Agent proporciona la dirección del despliegue y
  la configuración lista para copiar para clientes MCP comunes.

## Exportación de conversaciones

- El Agent y el Playground exportan una conversación como una página HTML
  autocontenida, una imagen PNG o en formato JSON. Estos reemplazan el informe en Markdown. Una exportación
  se construye a partir de lo que muestra la página: se omiten las huellas dactilares de las claves,
  los tokens y los identificadores de ejecución, y la página no permite acceso a la red.

## Cuota

- Las credenciales de suscripción de Grok muestran su ventana de uso, los planes de Kimi sin
  límite semanal muestran su uso, y el límite mensual del plan gratuito de Codex ya
  no se etiqueta como una ventana de cinco horas.
- Una lectura que devuelve un uso no publicado se muestra como tal, en lugar de
  aparecer como una credencial que nunca fue comprobada.

## Teléfonos

- La primera pantalla del Agent, las listas de comandos, la tarjeta de aprobación y el campo de escritura están
  adaptados para teléfonos, y las acciones de la página se hacen a un lado mientras el teclado está visible.
- Las tablas mantienen cada cifra en una sola línea y permiten desplazamiento horizontal; los gráficos se dibujan con
  el ancho de la pantalla, por lo que el texto de sus ejes permanece legible.
- La etiqueta de una acción de icono ya no aparece sobre un control que no ha sido tocado.

## Fiabilidad y seguridad

- Las cargas útiles de uso ya recibidas se conservan cuando una suscripción se cierra o el
  proceso se detiene, y la canalización de ingesta finaliza antes de que se cierre la base de datos.
- La copia de seguridad tomada antes de una migración incluye las filas que aún estaban en
  el registro de transacciones pendientes (write-ahead log).
- El cliente de gestión de CPA no sigue redireccionamientos, el estado ascendente y
  el texto de error se ocultan (redacted) antes de llegar a una respuesta ordinaria, y una escritura
  en el campo de un archivo de auth responde con `409` si el archivo cambió después de haber sido mostrado.
- El estado del recolector informa `failing` tras una captura fallida hasta la siguiente
  exitosa, and una operación que sigue ejecutándose se lee como `executing` en
  lugar de `uncertain`.

## Notas de actualización

- Realice una copia de seguridad de la base de datos SQLite persistente y conserve su clave maestra antes
  de actualizar; siga las instrucciones de `docs/ops/sqlite-operations.md`. Esta versión añade una
  migración, `036_agent_image_documents`, que reconstruye la tabla `agent_documents`
  para almacenar imágenes del Agent. Se ejecuta automáticamente en el primer inicio y no
  se puede revertir mediante un downgrade.
- Un proxy inverso que configure su propia Content-Security-Policy debe mantener
  `frame-src 'self' blob:`; las interfaces generadas del Agent se dibujan en
  marcos aislados (sandboxed frames).
- El endpoint MCP remoto acepta la clave de gestión de CPA, la cual equivale a
  la de un administrador. Sirva la consola a través de HTTPS antes de conectar un
  agente desde otra máquina.
- La sesión almacenada del Playground conserva su clave, modelo y esfuerzo de razonamiento. Un
  esfuerzo en texto libre fuera de los niveles con nombre permanece seleccionado hasta que
  se modifique.
- Compose continúa usando `latest` por defecto. Para fijar esta versión después de su
  publicación, utilice `wiziscool/oh-my-cpa:v0.2.0` o `wiziscool/oh-my-cpa:0.2.0`.
